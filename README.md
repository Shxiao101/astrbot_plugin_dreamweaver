# QQ 互动故事 · AstrBot 插件

在 QQ 私聊或群聊里体验 AI 主持的分支文字冒险。所有指令回复均以一条合并聊天记录发送，长文拆分在同一张卡片内部，避免刷屏。基于 InternalBeyond Story 的玩法和提示词改编，非官方作品。

## 安装

要求 AstrBot **4.9.2 或以上**，通过 **OneBot v11 / NapCat** 接入 QQ，并配置能输出 JSON 的聊天模型。群聊和私聊均使用合并转发，平台需要支持该消息类型。仅使用 Python 标准库及 AstrBot，无额外 pip 依赖。

1. 在 AstrBot WebUI 插件管理中选择 ZIP 安装，上传 `astrbot_plugin_interactive_story.zip`。
2. 也可把源码文件夹放入 `AstrBot/data/plugins/astrbot_plugin_interactive_story`，然后重启 AstrBot。
3. 在插件管理里打开“互动故事 → 配置”，通过下拉菜单选择故事模型，并编辑提示词等参数。默认每次请求超时120秒。
4. 确保 AstrBot 的唤醒前缀包含 `/`，并允许目标群/私聊响应指令。群聊如配置了必须 @，请同时 @ 机器人。
5. 发送 `/story` 或 `/story 开始`。不需要单独填 API Key。

## 插件面板配置

在 AstrBot WebUI 的“插件 → 互动故事 → 配置”中调整以下选项，点击保存后自动热重载，无需修改代码。

| 设置 | 默认值及用途 |
|---|---|
| 故事主持模型 | 下拉选择已配置的聊天模型；留空跟随开局时会话模型 |
| 故事主持提示词 | 多行编辑主持风格、角色、世界观和结局设计；程序追加本局参数及必需JSON格式 |
| 通关存档提示词 | 多行编辑通关设定文档的内容与风格 |
| 默认故事题材／恐怖度 | 奇幻／无；QQ开局指令可单次指定 |
| 最早／最晚结局轮次 | 12／16；范围1–64，最早不能大于最晚 |
| 随机故事／自定义剧本每轮目标字数 | 180／200；范围50–1500，为模型写作目标 |
| 每次模型请求超时 | 120秒；范围10–600 |

模型、提示词、轮数和字数在开局时随故事保存。修改配置后，新开局及“重玩”采用新配置；当前故事继续使用原设置。超时在保存配置后即时用于后续请求。升级前的故事自动沿用旧版默认提示词及12–16轮规则，进度可以继续恢复。

## 指令

| 指令 | 用途 |
|---|---|
| `/story` | 帮助 |
| `/story 开始 [题材] [恐怖度]` | 随机故事；省略参数时使用面板默认值 |
| `/story 剧本 <题材> <恐怖度> <正文>` | 自定义剧本，1–3000字，支持多行 |
| `/story 1`、`/story 2`、`/story 3` | 选择对应选项 |
| `/story 状态` | 重发当前剧情、轮次及选项，不调用AI |
| `/story 重试` | 重试未完成的开场或选择，不重复推进 |
| `/story 退出` | 暂停并保存，废弃在途生成结果 |
| `/story 继续` | 恢复；中断回合会提示再发送“重试” |
| `/story 存档` | 保存无剧透游玩记录；结局后整理完整设定 |
| `/story 记录 [页码]` | 分页查看最近一次存档，默认第1页 |
| `/story 重玩` | 保存旧记录，保留题材、恐怖度和剧本，使用面板当前模型及主持设置重开 |

题材：**奇幻、神秘学、推理悬疑、恋爱、科幻**。恐怖度：**无、低、中、高**。

示例：

```text
/story 开始 推理悬疑 低
/story 2
/story 存档
/story 退出
/story 继续
```

```text
/story 剧本 科幻 无 你是空间站里最后一名维修员。
角色：失忆的导航AI、迟到三十年的货船船长。
目标：查出空间站为什么每天重复同一天。
```

每个“平台会话＋QQ用户”拥有独立进度。同一人在不同群和私聊中的游戏互不影响。群里显示玩家编号；群消息中的故事、剧本和存档均对群成员可见。普通聊天、裸数字和其他用户的选择不会推进你的故事。

## 游戏与存档

- 每轮目标字数在面板配置，默认180字（自定义剧本200字），三个行动选项；情绪以文字标记显示。
- 按原版由AI即兴主持，默认提示词要求三个普通结局和一个隐藏结局，默认12–16轮收束。插件按本局配置拒绝提前结局和超过最晚轮次的继续剧情，格式/轮次异常最多修复一次，再失败可手动重试。
- 多结局不是固定、可证明遍历的分支树；重玩会重新生成，不保证同一剧情。完整设定中未走过的分支明确标注为AI补全。
- 模型上下文仅包含本局故事，不读取普通聊天、人设记忆或调用工具。开局固定模型ID；删除该模型后需恢复对应配置才能继续。
- 每个成功回合写入 AstrBot 插件 KV 后再回复。模型或写入失败不增加已提交轮次；重启、热重载后用“状态/继续/重试”恢复。消息发送失败不会回滚已存进度，可用“状态”重发。
- 同一局生成期间拒绝其他推进操作。“退出”可立即使本轮结果失效，但不保证取消已发往模型服务的请求或费用。
- 中途存档不会请求额外AI总结。通关存档额外调用一次AI；失败仍保留实际记录。“记录”显示最近一次存档，新的存档会替换其展示内容。
- 所有完整存档另外保存为 UTF-8 TXT：`data/plugin_data/astrbot_plugin_interactive_story/archives/`。文件名自动生成；不接受用户文件路径。历史文件不会自动清理，管理员可按需要备份清理。
- 每个玩家每个会话仅保留一局当前进度。重玩会替换当前进度，旧记录保存为TXT，并成为最近存档；已通关后直接开新局也会先保存旧记录为TXT。

## 测试与联调

在插件源码目录运行：

```powershell
python -m unittest discover -s tests -v
```

自动测试使用模拟模型和存储，验证玩法、隔离、恢复和失败行为；不需要 API Key。真实 QQ 联调需已运行的 AstrBot、模型和 QQ 连接：先私聊开局，再让同群两人各自开局与选择，重载插件后继续，最后完成一局并查看存档。当前交付未执行真实 QQ 联调。
